## Project Overview

The **Smart Hygiene Risk Prediction System** is a complete, end-to-end machine learning project that analyzes facility inspection data and predicts the hygiene risk category (`Low`, `Medium`, or `High`) for each facility based on relevant inspection parameters.

The system includes data preprocessing, exploratory data analysis, feature selection, model training, evaluation, visualization, prediction, and a REST API built with FastAPI.

> ⚠️ **SYNTHETIC DATA DISCLOSURE**
>
> This project uses a **programmatically generated synthetic dataset** for educational purposes.
> No real facilities, locations, or inspection results are represented.
> The target variable `hygiene_risk` is **rule-generated** (not independently verified by any public-health authority).
> A model trained on rule-generated labels learns to approximate that rule — it does **not** predict real-world hygiene outcomes.
> **Do NOT use predictions from this system as official safety certifications.**

## Dataset Description

### Source

**Synthetic** — generated by `data/generate_data.py` using NumPy with `random_seed=42`.

### Fields

| Column | Type | Description |
|--------|------|-------------|
| `facility_id` | string | Unique identifier (e.g. FAC0001) |
| `location` | categorical | Inspection zone (Zone A–E) |
| `cleanliness_score` | float | 0–100; higher = cleaner |
| `odor_score` | float | 0–10; higher = worse odor |
| `waste_level` | categorical | Low / Medium / High |
| `water_availability` | categorical | Yes / No |
| `footfall` | float | Daily visitor count (50–500) |
| `complaints` | float | Registered complaints (0–20) |
| `inspection_date` | date | 2023-01-01 – 2024-12-31 |
| `hygiene_risk` | categorical | **Rule-generated target**: Low / Medium / High |

### Labeling Rule (transparent, documented)

```
risk_score = (100 - cleanliness_score) × 0.40
           + odor_score                × 1.50
           + waste_level_num           × 5.00   # Low=0, Medium=1, High=2
           + (1 - water_num)           × 10.00  # Yes=1, No=0
           + complaints                × 1.20
           + footfall                  × 0.02
           + N(0, 2.0)                           # small random noise

hygiene_risk = "Low"    if risk_score < 40
             = "Medium"  if 40 ≤ risk_score < 70
             = "High"    if risk_score ≥ 70
```

Missing values (~3% per numeric column) are introduced to simulate real-world data quality.

## Data Preprocessing

Implemented in [`src/data_preprocessing.py`](src/data_preprocessing.py).

### Pipeline steps

1. **Load** CSV and report shape, dtypes, missing values, and duplicates.
2. **Drop** `facility_id` (unique identifier) and `location` (not used as model features).
3. **Extract date features**: `inspection_month`, `inspection_dayofweek` from `inspection_date`.
4. **Separate** features (X) from target (y = `hygiene_risk`).
5. **Stratified train/test split** (80/20, `random_state=42`).
6. **Numeric pipeline** (fitted on training data only):
   - `SimpleImputer(strategy="median")`
   - `StandardScaler()`
7. **Categorical pipeline** (fitted on training data only):
   - `SimpleImputer(strategy="most_frequent")`
   - `OneHotEncoder(handle_unknown="ignore")`
8. **ColumnTransformer** combines both pipelines.

> Preprocessing is fitted exclusively on training data to prevent data leakage.

## Feature Selection

Implemented in [`src/feature_selection.py`](src/feature_selection.py).

- Method: **Random Forest Gini importance** (trained on training set only).
- `facility_id` and `location` are excluded before feature selection.
- Features with importance ≥ 1% are retained.
- All key inspection features (cleanliness, odor, waste, water, footfall, complaints) are retained.
- See `outputs/feature_importance.png` for the ranked chart.

> Feature importance reflects approximation of the labeling rule, not real-world predictive relevance.

## Model Evaluation Results

> ⚠️ All metrics are computed on **synthetic, rule-generated** labels. They do **not** represent real-world predictive performance.

| Model | Accuracy | Precision (macro) | Recall (macro) | F1 (macro) |
|-------|----------|-------------------|----------------|------------|
| **Logistic Regression** | **0.9350** | **0.9088** | **0.9575** | **0.9307** |
| Random Forest | 0.8850 | 0.8658 | 0.8682 | 0.8668 |

> ✅ **Selected model: Logistic Regression** (higher macro F1 = 0.9307)

### Discussion

- **Random Forest** typically outperforms Logistic Regression on this dataset because the labeling rule introduces non-linear thresholds.
- **Recall** is particularly important for "High" risk facilities: failing to identify a genuinely high-risk facility has greater real-world consequences than a false alarm.
- **Accuracy alone is misleading** when classes are imbalanced; macro-averaged F1 is more informative.
- High accuracy on rule-generated labels means the model approximates the rule well — it says **nothing** about real-world generalization.

## Limitations and Future Improvements

### Current Limitations

| Limitation | Details |
|-----------|---------|
| Synthetic data | No real inspection records; model learns a rule, not real hygiene risk |
| Rule-generated labels | Target is derived from features; evaluation does not reflect real-world accuracy |
| No real validation | Cannot claim real-world predictive performance |
| Static features | Date features default to mid-year/mid-week when not provided |
| Single model saved | Only the best model is persisted |

### Suggested Future Improvements

- Replace the synthetic dataset with real hygiene inspection records from a verified public source.
- Obtain independently verified target labels from public-health inspectors.
- Add cross-validation (k-fold) for more robust performance estimates.
- Implement hyperparameter tuning (GridSearchCV / RandomizedSearchCV).
- Add SHAP explainability for individual predictions.
- Containerise the API with Docker.
- Add authentication and rate limiting to the API.
- Integrate monitoring and logging for production deployment.
